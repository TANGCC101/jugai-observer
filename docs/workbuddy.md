# WorkBuddy 网关接入

使用部署者自己有权使用的网关和接入凭证。网站不持有上游账号的登录或刷新令牌，不管理账号轮换。

在后端 `.env` 配置 `LLM_BASE_URL`（含 `/v1`）、`LLM_API_KEY`（网站专用接入密钥）、`LLM_MODEL=deepseek-v4.1-flash`，并设置 `LLM_EXTRA_JSON={"thinking":{"type":"disabled"}}`。凭证不写入源码、镜像或浏览器。

部分网关即使收到非流式请求，也返回 `text/event-stream`。模型接收层根据响应 Content-Type 合并 SSE 的正文片段，保留末尾 usage、响应 ID 与 finish_reason，然后继续走原有结构校验和请求回执。普通 JSON 响应保持原有处理。缺失结束标记的请求保留未知状态，不接受部分答案；完整但格式错误或带错误事件的回答被记为失败，不能发布。

启用前在后台设置 `llm` 服务的调用次数限制。此部署初始值为每分钟2次、每小时10次、滚动一天30次；不是人民币限额或 token 限额。小规模真实文章的摘要与分类仍需人工检查，不能由接口可连接推断质量。

确认网站容器可以访问网关后，再将 `MODEL_CALLS_ENABLED=true` 并重新部署后端。单纯重启旧容器不会重新载入修改后的环境变量。RSS 使用独立 `COLLECT_ENABLED` 开关。

暂停模型处理：将 `MODEL_CALLS_ENABLED=false` 并重新部署，RSS 可继续抓取。若停用整个接入，可在网关停用网站专用接入密钥。不要移除其他客户端的凭证，也不要为此扩大网关的公网或局域网暴露范围。

模型标签由网关报告，连通和 JSON 测试不证明上游真实模型身份；费用与额度以网关及其上游实际记录为准。
